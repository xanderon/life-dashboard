Stack Frame, Call Stack, and Stack vs Heap

A clean interview-focused study page about how function calls use stack frames, what the call stack stores, and how stack memory differs from heap memory in JavaScript.

Definition

What is the stack?

  • Memory used for execution.
  • Stores function calls and local execution state.
  • Works like LIFO: last in, first out.
  • Fast and limited in size.

What is the heap?

  • Memory used for dynamically allocated data.
  • Stores objects, arrays, functions, closures, and other complex values.
  • More flexible, but slower than the stack.
  • Managed by the JavaScript engine and garbage collector.

Most important interview sentence

The stack stores function calls, local variables, and references. The heap stores the actual objects and dynamically allocated data.

Intuition

Why does the stack exist?

  • Every function call needs temporary memory.
  • The runtime must know where to return after a function finishes.
  • It must also keep function parameters and local variables somewhere.

Why does the heap exist?

  • Some values must live longer than one function call.
  • Objects can be large and flexible.
  • Closures can keep values alive even after a function returns.

Mental model

Think of the stack as a short-term execution area and the heap as long-term storage for dynamic data.

How It Works

1. Function call

A new stack frame is pushed onto the call stack.

2. Function runs

The frame stores parameters, local variables, and the return location.

3. Function returns

The frame is popped from the stack and disappears.

What is a stack frame?

A stack frame is the small block of execution data created for one function call. It usually contains:

  • function parameters
  • local variables
  • return address
  • temporary execution data

Key idea

  • c() is on top because it is the current function.
  • When c() finishes, its frame is removed first.
  • Then execution returns to b(), then a().

Examples

Primitive values

Primitives are copied by value.

let x = 5;
let y = x;
Stack
x → 5 y → 5
Heap
(empty)

Object reference

let user = { name: "Alex" };
let admin = user;
Stack
user → 0x1A2B admin → 0x1A2B
Heap
0x1A2B → { name: "Alex" }

Common confusion

admin = user does not create a new object. Both variables point to the same heap object.

Function frame

function sum(a, b) {
  let result = a + b;
  return result;
}

sum(2, 3);
Call Stack
sum frame --------- a → 2 b → 3 result → 5 return address → global
What happens after return?
The entire sum frame is removed. Only the caller remains on the call stack.

Object created inside a function

function createUser() {
  let user = { name: "Alex" };
  return user;
}

let u = createUser();
During execution
Stack: createUser frame user → 0x1A2B Heap: 0x1A2B → { name: "Alex" }
After return
Stack: u → 0x1A2B Heap: 0x1A2B → { name: "Alex" }

Closure keeps data alive

function counter() {
  let count = 0;

  return function () {
    count++;
    return count;
  };
}

let c = counter();

Why is this important?

The function counter() returns, but count can still live because the inner function keeps a reference to it.

Step-by-Step Explanation

  1. The program starts with a global execution context.
  2. When a function is called, a new stack frame is pushed.
  3. That frame stores parameters and local variables.
  4. If the function creates an object, the object lives on the heap.
  5. The stack frame stores only the reference to that object.
  6. When the function returns, its frame is popped.
  7. If something still references the heap object, it stays alive.
  8. If nothing references it, garbage collection can remove it later.

Line-by-Line Explanation

function sum(a, b) {
  let result = a + b;
  return result;
}

sum(2, 3);

function sum(a, b)

Defines a function. No frame exists yet.

sum(2, 3)

Calls the function. A new sum frame is pushed onto the stack.

a and b

These are stored inside the current stack frame as local execution data.

let result = a + b;

result is another local variable inside the same frame.

return result;

The value is returned to the caller.

After return

The whole frame is removed from the stack.

Common Mistakes and Confusions

Mistake #1

Thinking that variables and objects always live in the same place.

Fix: the variable may be on the stack, but the object itself is on the heap.

Mistake #2

Thinking that admin = user copies the object.

Fix: it copies the reference, not the object.

Mistake #3

Thinking every function has one permanent frame.

Fix: every function call creates a new frame.

Mistake #4

Thinking closures keep nothing after a function returns.

Fix: closures can keep referenced values alive on the heap.

Complexity

Main stack operations

  • push a frame: O(1)
  • pop a frame: O(1)

Space

  • Call stack space depends on call depth.
  • For deep recursion, stack usage can grow to O(n).

When does complexity matter here?

Mostly when talking about recursion. Too many nested calls can cause Maximum call stack size exceeded.

Interview Explanation Version

20–30 second answer

The stack stores function calls and local execution data, while the heap stores dynamically allocated objects. In JavaScript, objects are usually on the heap, and variables on the stack hold references to them. Each function call creates a stack frame, and when the function returns, that frame is removed.

45-second stronger answer

The stack is used for execution, so it keeps stack frames for active function calls. A frame contains things like parameters, local variables, and the return address. The heap is used for objects and other dynamic data. In JavaScript, if I create an object inside a function, the frame usually stores only a reference, while the object itself lives on the heap. This is why shared references, closures, and stack overflow all make sense once you understand stack vs heap.

Pattern to Remember

Short memory rule:

  • Stack = function calls, local state, references.
  • Heap = actual objects and dynamic data.
  • Frame = one function call's execution box.
  • Recursion = more frames pushed onto the stack.
  • Closure = data can survive after the outer function returns.

Summary

  • Every function call creates a new stack frame.
  • Stack frames hold parameters, locals, and return information.
  • The stack stores references; the heap stores the actual objects.
  • Primitive values are copied by value.
  • Objects are shared through references unless explicitly copied.
  • Closures can keep data alive after a function returns.

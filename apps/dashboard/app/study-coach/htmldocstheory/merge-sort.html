Technical Interview Study Page

Merge Sort

A classic divide and conquer sorting algorithm. It is important in interviews because it is clean, predictable, stable, and a great way to show that you understand recursion, array splitting, and merging sorted data.

Algorithms Sorting Divide and Conquer Recursion JavaScript Interview Prep

1. Problem Statement

Given an array of numbers, sort it in ascending order using Merge Sort.

Example goal: turn [5, 3, 8, 4, 2] into [2, 3, 4, 5, 8].

2. Examples

Example 1

Input: [5, 3, 8, 4, 2]

Output: [2, 3, 4, 5, 8]

Example 2

Input: [4, 1, 3, 2]

Output: [1, 2, 3, 4]

3. Main Idea / Intuition

Merge Sort works in two big phases:

  1. Split the array into smaller halves until each piece has 1 element.
  2. Merge those small sorted pieces back together in sorted order.

A single element is already sorted. The real work is in the merge(left, right) step.

4. Visual Overview

Input: [8, 3, 5, 2] Split phase: [8, 3, 5, 2] / \ [8, 3] [5, 2] / \ / \ [8] [3] [5] [2] Merge phase: [8] + [3] → [3, 8] [5] + [2] → [2, 5] Final merge: [3, 8] + [2, 5] → [2, 3, 5, 8]

5. Step-by-Step Walkthrough

Step 1: Start with the full array
[5, 3, 8, 4, 2]
Step 2: Split into halves
Left = [5, 3]
Right = [8, 4, 2]
Step 3: Keep splitting recursively
[5, 3] becomes [5] and [3]
[8, 4, 2] becomes [8] and [4, 2]
[4, 2] becomes [4] and [2]
Step 4: Merge small sorted arrays
[5] + [3] → [3, 5]
[4] + [2] → [2, 4]
Step 5: Merge bigger sorted arrays
[8] + [2, 4] → [2, 4, 8]
Step 6: Final merge
[3, 5] + [2, 4, 8] → [2, 3, 4, 5, 8]

6. The Most Important Part: How merge() Works

Suppose we already have two sorted arrays:

left = [3, 8]

right = [2, 5]

We compare the current elements one by one:

left = [3, 8] i right = [2, 5] j result = [] Compare left[i] and right[j]: 1) 3 vs 2 → take 2 result = [2] 2) 3 vs 5 → take 3 result = [2, 3] 3) 8 vs 5 → take 5 result = [2, 3, 5] right is finished, so append the rest of left: result = [2, 3, 5, 8]

Key idea: the while loop is not doing the recursive splitting. It is only used to merge two already sorted arrays.

7. Final JavaScript Solution

function mergeSort(arr) {
  // Base case:
  // If the array has 0 or 1 element, it is already sorted.
  if (arr.length <= 1) {
    return arr;
  }

  // Find the middle index
  const mid = Math.floor(arr.length / 2);

  // Split the array into left and right halves
  const leftHalf = arr.slice(0, mid);
  const rightHalf = arr.slice(mid);

  // Recursively sort each half
  const sortedLeft = mergeSort(leftHalf);
  const sortedRight = mergeSort(rightHalf);

  // Merge the two sorted halves
  return merge(sortedLeft, sortedRight);
}

function merge(left, right) {
  const result = [];
  let i = 0;
  let j = 0;

  // Compare elements from both arrays
  while (i < left.length && j < right.length) {
    if (left[i] < right[j]) {
      result.push(left[i]);
      i++;
    } else {
      result.push(right[j]);
      j++;
    }
  }

  // Add any remaining elements
  while (i < left.length) {
    result.push(left[i]);
    i++;
  }

  while (j < right.length) {
    result.push(right[j]);
    j++;
  }

  return result;
}

// Example
console.log(mergeSort([5, 3, 8, 4, 2])); // [2, 3, 4, 5, 8]

8. Line-by-Line Explanation

mergeSort(arr)

  • if (arr.length <= 1): stop condition for recursion.
  • mid: where we split the array.
  • slice(0, mid): left half.
  • slice(mid): right half.
  • mergeSort(leftHalf): recursively sort left.
  • mergeSort(rightHalf): recursively sort right.
  • merge(sortedLeft, sortedRight): combine them into one sorted array.

merge(left, right)

  • result: final merged array.
  • i: pointer for left.
  • j: pointer for right.
  • while (i < left.length && j < right.length): keep comparing while both arrays still have elements.
  • If left[i] is smaller, push it and move i.
  • Otherwise, push right[j] and move j.
  • After the loop, append the remaining elements from whichever side is not finished.

9. Why It Uses Recursion + a Second Function

Why recursion?

Recursion is used for the split phase. Merge Sort naturally says: “sort the left half” and “sort the right half,” and those are just smaller versions of the same problem.

Why a second function?

The second function, usually merge(), handles the merge phase. It solves a different sub-problem: given two sorted arrays, combine them efficiently.

Interview answer: “Merge Sort is usually written with recursion for splitting, and a helper function for merging.” There is also an iterative version called bottom-up merge sort, but the recursive one is the most common in interviews.

10. Common Mistakes

  • Confusing the roles: recursion splits, merge() combines.
  • Forgetting the base case: without arr.length <= 1, recursion never stops.
  • Not adding leftover elements: after the main while, one side may still have items.
  • Using expensive operations like shift() repeatedly: in JavaScript, shift() is typically O(n), which hurts performance.
  • Thinking merge sort is in-place: the standard version uses extra memory.

11. Complexity

Case Time Complexity Why
Best O(n log n) Still splits and merges every level
Average O(n log n) Balanced divide + linear merge work per level
Worst O(n log n) Unlike quicksort, merge sort stays predictable
Space O(n) Extra arrays are created during merging

Intuition for O(n log n):

  • There are about log n levels of splitting.
  • At each level, the total work done by merging is about n.
  • So total work is n × log n.

12. Interview Explanation Version

30-second version:
“Merge Sort is a divide-and-conquer sorting algorithm. It recursively splits the array into halves until each subarray has one element, then merges those sorted subarrays back together. The merge step is linear, and because there are log n levels of splitting, the total time complexity is O(n log n). It is stable, but it uses O(n) extra space.”

13. Pattern to Remember

Pattern: split → solve subproblems → merge results

This same interview pattern appears in:

  • Merge Sort
  • Binary tree recursion
  • Divide and conquer problems
  • Problems like “merge two sorted arrays/lists”

14. Optional Brute Force Comparison

Bubble Sort mindset

Compare neighbors again and again until everything is sorted.

Time: O(n²)

Merge Sort mindset

Break the problem into smaller sorted parts, then merge intelligently.

Time: O(n log n)

15. Final Takeaway

If you remember only one thing, remember this:

Merge Sort = recursion for splitting + while loop for merging.

The recursion is not the scary part once you see that it just keeps cutting the array into smaller pieces. The merge() function is the real engine: it combines two sorted arrays into one sorted result.

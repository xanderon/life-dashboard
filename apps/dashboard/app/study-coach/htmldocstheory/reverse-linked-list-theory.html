Easy Linked List Three Pointers Must Know

#206 Reverse Linked List

Building block pentru palindrome, k-group reversal, reorder list și altele.

Problem Statement

Dată head-ul unei liste înlănțuite, întoarce lista inversată.

Modifici lista in-place — fără a aloca o nouă structură de date.

Input
head = [1, 2, 3, 4, 5]
Output
[5, 4, 3, 2, 1]
Edge Case — single node
head = [1] → [1]
Edge Case — empty list
head = null → null

Intuiție & Mental Model

🚂 Analogia trenului

Imaginează-ți vagoane de tren cuplate: fiecare știe doar cine e în față. Inversarea înseamnă că decuplezi fiecare vagon și îl cuplezi în sens invers. La final, locomotiva devine ultimul vagon și viceversa.

De ce există această operație?

O listă simplă merge într-o singură direcție. Nu poți parcurge înapoi fără:

  • un stack auxiliar O(n) space
  • sau inversarea pointer-ilor in-place O(1) space ← soluția optimă

Reversarea e un building block pentru zeci de probleme mai complexe.

Algoritmul — Three Pointers

Avem nevoie de 3 pointeri care avansează simultan:

  • prev — nodul deja procesat (start: null)
  • curr — nodul curent pe care îl procesăm (start: head)
  • next — salvăm curr.next înainte să-l suprascriem

La fiecare iterație, 4 pași:

  1. Salvează next = curr.next  → nu pierdem restul listei
  2. Inversează: curr.next = prev  → pointer-ul merge înapoi
  3. Avansează: prev = curr
  4. Avansează: curr = next

Soluția JavaScript

reverse-linked-list.js 
// Definition for singly-linked list node
function ListNode(val, next = null) {
  this.val = val;
  this.next = next;
}

// ─── Iterative — O(n) time, O(1) space ───────────────────────────
function reverseList(head) {
  let prev = null;  // the "already reversed" side
  let curr = head;  // current node being processed

  while (curr !== null) {
    const next = curr.next; // 1️⃣  save next before we overwrite it
    curr.next = prev;        // 2️⃣  reverse the pointer
    prev = curr;             // 3️⃣  advance prev
    curr = next;             // 4️⃣  advance curr
  }

  return prev; // prev is the new head (curr is null at this point)
}
recursive-version.js — O(n) space! 
// ─── Recursive — O(n) time, O(n) space (call stack!) ────────────
function reverseListRecursive(head) {
  // Base case: empty list or single node
  if (head === null || head.next === null) return head;

  // Recursively reverse the rest of the list
  const newHead = reverseListRecursive(head.next);

  // Make next node point back to current
  head.next.next = head;

  // Cut current node's forward link
  head.next = null;

  return newHead;
}

// ⚠️  Avoid in interviews unless explicitly asked.
// Each recursive call adds a frame to the call stack → O(n) space.
// For a list of 100,000 nodes this can cause a stack overflow.

Explicație Linie cu Linie

let prev = null

La început, "partea inversată" este goală. Primul nod procesat va trebui să pointeze spre null (devine noul tail).

const next = curr.next

Cel mai important pas. Dacă nu salvezi next înainte de a suprascrie curr.next, pierzi accesul la restul listei. Aceasta e greșeala #1 la interviu.

curr.next = prev

Inversarea propriu-zisă. Nodul curent nu mai pointează spre dreapta — pointează spre stânga, spre ce am procesat deja.

return prev

La ieșirea din buclă, curr === null. prev este ultimul nod procesat, care este noul head. Dacă returnezi curr, returnezi null. Greșeala #2 la interviu.

Greșeli Comune

Greșeala #1 — Uiți să salvezi next

// ❌ WRONG — lost the rest of the list!
curr.next = prev;
curr = curr.next; // curr is now null, not the next real node!

// ✅ CORRECT
const next = curr.next; // save first
curr.next = prev;
curr = next;

Greșeala #2 — Returnezi curr în loc de prev

// ❌ WRONG — returns null (curr = null when loop exits)
return curr;

// ✅ CORRECT — prev = the last processed node = new head
return prev;

Greșeala #3 — Preferi recursivul fără să menționezi spațiu O(n)

Recursivul pare mai elegant, dar fiecare apel adaugă un frame pe call stack. Pentru liste mari poate provoca stack overflow. Menționează explicit trade-off-ul.

Greșeala #4 — Nu tratezi edge cases

Complexitate

Variantă Time Space De ce?
Iterativ ✅ O(n) O(1) Vizitezi fiecare nod o singură dată. Doar 3 pointeri, indiferent de n.
Recursiv O(n) O(n) n apeluri recursive pe call stack simultan = O(n) memory.
Cu stack auxiliar O(n) O(n) Stochezi toate valorile, apoi le rescrii. Simplu dar ineficient.

Iterativ vs Recursiv

✅ Iterativ — preferabil

  • Space O(1) — constant
  • Nu risc de stack overflow
  • Mai ușor de debug
  • Răspuns clar la interviu

⚠️ Recursiv — cu rezerve

  • Space O(n) — call stack
  • Stack overflow pentru liste mari
  • Cod mai elegant vizual
  • Folosește doar dacă e cerut

Întrebări Frecvente de Interviu

Q: Care e diferența iterativ vs recursiv?

A: Iterativ = O(1) space (doar 3 pointeri). Recursiv = O(n) space din call stack. La o listă de 100k noduri, recursivul poate cauza stack overflow.

Q: Ce returnezi la final și de ce?

A: Returnez prev, nu curr. La ieșirea din buclă, curr este null iar prev pointează spre ultimul nod procesat — care este noul head.

Q: Ce se întâmplă cu lista originală?

A: E modificată in-place. Dacă ai nevoie de structura originală, trebuie să o copiezi înainte.

Q: Cum tratezi edge cases?

A: head = null: bucla nu pornește, returnăm null. head cu un singur nod: o iterație, nodul pointează spre null, returnăm nodul. Ambele funcționează fără if explicit.

Capcane & Trick Questions

"Poți face asta cu 2 pointeri, fără next temporar?"

Nu. Ai nevoie de next temporar, altfel pierzi restul listei când suprascrii curr.next. Poți folosi destructuring în JS: [prev, curr, curr.next] = [curr, curr.next, prev] — dar tot sunt 3 valori.

"Ce se întâmplă dacă inversezi de două ori?"

Obții lista originală. Reversal este idempotent aplicat de două ori: reverse(reverse(list)) = list.

"Este lista mutată sau copiată?"

Mutată. Inversezi pointer-ii existenți in-place. Nodurile sunt aceleași obiecte în memorie.

Răspuns de Interviu — 30 secunde

„Reverse Linked List înseamnă să inversezi direcția tuturor pointer-ilor next. Folosesc trei pointeri: prev inițializat cu null, curr pornind de la head, și next pentru a salva temporar legătura înainte să o suprascriu — altfel pierdem restul listei. La fiecare pas fac curr.next = prev, avansez prev la curr și curr la next. La final, prev pointează spre noul head — curr este null la ieșire. Time O(n), Space O(1). Prefer varianta iterativă față de recursivă deoarece recursivul consumă O(n) space pe call stack."

Feynman — pentru un copil de 10 ani

Ai 5 cuburi legate cu sfori: [1]→[2]→[3]→[4]→[5].

Vrei să meargă în ordine inversă. Ce faci?

Iei primul cub, tai sfoara care merge spre [2], și legi o sfoară nouă spre... nimic (null). Iei [2], tai sfoara spre [3], legi o sfoară nouă spre [1]. Continui până la capăt.

La final ai [5]→[4]→[3]→[2]→[1]→null. Ai folosit doar mâinile tale — nicio cutie extra!

Pattern de Reținut

Pattern: Three-Pointer In-Place Reversal Init: prev = null, curr = head Loop guard: curr !== null Step 1: save next = curr.next // always first! Step 2: curr.next = prev // reverse Step 3: prev = curr // advance prev Step 4: curr = next // advance curr Return: prev // NOT curr (curr = null) Time: O(n) Space: O(1)

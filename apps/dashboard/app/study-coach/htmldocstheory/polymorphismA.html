Polymorphism

Same method call, different behavior depending on the concrete object. This is one of the most important OOP ideas to explain clearly in interviews, especially without mixing it up with inheritance or abstraction.

OOP JavaScript TypeScript / JS Thinking Interview Theory Polymorphism vs Inheritance

Definition

Core idea

Polymorphism means that different objects can be treated through the same interface, while each object can provide its own implementation of the behavior.

In simple interview language: same call, different result based on the real object.

What is correct and what is not

Correct intuition

If you have a function that receives an Animal and calls animal.speak(), that function does not need to know whether it got a dog or a cat.

Important correction

Polymorphism is not the same thing as inheritance. Inheritance may help you implement polymorphism, but polymorphism is really about one common contract + multiple concrete behaviors.

Intuition

Think like this: a program says payment.pay(). It does not care if the payment is card, Apple Pay, Google Pay, or something else.

The caller uses a generic contract. Each concrete payment type handles the details differently inside, but the outside interaction remains the same.

Mental model

1. Define a common behavior Example: speak() or pay()
2. Create multiple concrete implementations Dog.speak(), Cat.speak(), CardPayment.pay()
3. Use them through the common shape The caller works with Animal or PaymentMethod
4. Runtime picks the real behavior The actual object decides what happens
One-line memory hook

Polymorphism = one interface, many forms.

Or even shorter:
same method call → different behavior

Main interview example: Animal

class Animal {
  speak() {
    console.log("Some generic sound");
  }
}

class Dog extends Animal {
  speak() {
    console.log("Woof");
  }
}

class Cat extends Animal {
  speak() {
    console.log("Meow");
  }
}

function makeAnimalSpeak(animal) {
  animal.speak();
}

makeAnimalSpeak(new Dog());
makeAnimalSpeak(new Cat());
Why this is polymorphism

The function makeAnimalSpeak always does the same thing: it calls animal.speak(). But the result changes depending on the actual object.

Step-by-step explanation

  1. You define a parent type or common contract.
  2. Each subtype provides its own version of the same method.
  3. The caller depends only on the common shape, not on the exact subtype.
  4. At runtime, the actual object decides which method implementation runs.

Real-world example: Payment methods

class PaymentMethod {
  pay(amount) {
    throw new Error("pay() must be implemented");
  }
}

class CardPayment extends PaymentMethod {
  pay(amount) {
    console.log(`Paid ${amount} with card`);
  }
}

class ApplePayPayment extends PaymentMethod {
  pay(amount) {
    console.log(`Paid ${amount} with Apple Pay`);
  }
}

class GooglePayPayment extends PaymentMethod {
  pay(amount) {
    console.log(`Paid ${amount} with Google Pay`);
  }
}

function checkout(paymentMethod, amount) {
  paymentMethod.pay(amount);
}

checkout(new CardPayment(), 100);
checkout(new ApplePayPayment(), 100);
checkout(new GooglePayPayment(), 100);
Why interviewers like this example

Because it shows a practical design benefit: you do not keep adding if / else checks every time a new payment type appears.

Without polymorphism vs with polymorphism

Without polymorphism With polymorphism
Many if / switch branches One common method call
Adding a new type means editing old code Adding a new type usually means adding a new class/object
More fragile and harder to extend Cleaner and closer to Open/Closed Principle
Caller needs to know concrete details Caller only knows the shared contract

Line-by-line explanation of the key pattern

class Dog extends Animal

This means Dog is a specialized kind of Animal. Inheritance is being used here.

speak() inside Dog

This overrides the inherited version and defines dog-specific behavior.

function makeAnimalSpeak(animal)

The function depends on the generic type, not the concrete subtype.

animal.speak()

This is the polymorphic call. Same call site, but runtime behavior changes based on the real object.

Very important distinction: inheritance vs polymorphism

Concept Meaning
Inheritance One class extends another to reuse or specialize behavior.
Polymorphism Different objects respond to the same method call in different ways.
Interview trap

Do not say: "Polymorphism means reusing code through inheritance."

That sounds more like inheritance. A better answer is: polymorphism lets us use different objects through the same interface.

Polymorphism in JavaScript

In JavaScript, polymorphism does not always require classical inheritance. Because JavaScript is flexible, any object with the expected method can work. 

function speak(entity) {
  entity.speak();
}

const dog = {
  speak() {
    console.log("Woof");
  }
};

const robot = {
  speak() {
    console.log("Beep");
  }
};

speak(dog);
speak(robot);
Why this matters

This is still polymorphism. The caller uses the same method name, while different objects provide different implementations.

Prototype angle in JavaScript

When JavaScript tries to resolve a method like dog.speak(), it first looks on the object itself. If it does not find it there, it walks up the prototype chain. 

class Animal {
  speak() {
    console.log("Generic sound");
  }
}

class Dog extends Animal {}

const dog = new Dog();
dog.speak();
What happens conceptually

JavaScript checks the instance first. If the method is not found there, it checks Dog.prototype, then Animal.prototype, then higher in the chain.

Common mistakes / confusions

Mistake 1

Confusing polymorphism with inheritance.

Mistake 2

Saying polymorphism exists only with classes. In JavaScript it can also happen through object shape.

Mistake 3

Thinking the goal is only code reuse. The bigger goal is flexible design and interchangeable behavior.

Mistake 4

Using too many type checks like instanceof instead of relying on a shared contract.

Interview explanation version

Good 20-30 second answer

Polymorphism means that different objects can be treated through the same interface, while each object can implement the behavior differently. For example, if I call animal.speak(), a dog can say "Woof" and a cat can say "Meow". The caller uses the same method, but the runtime behavior depends on the real object.

Even shorter version

Polymorphism = same method call, different behavior depending on the concrete object.

Pattern to remember

Memory formula

generic caller + shared contract + specific implementation = polymorphism

Real-world use cases

Payments

Card, Apple Pay, Google Pay, bank transfer — all expose pay().

Storage backends

Local file system, S3, database blob storage — all expose save() or read().

Notifications

Email, SMS, push notification — all expose send().

UI handlers

Different widgets respond to the same event in different ways.

Final takeaway

What you should say confidently

Polymorphism is about treating different objects in a uniform way through a common contract, while allowing each one to behave differently internally.

Inheritance can help implement it, but inheritance and polymorphism are not the same concept.

Best interview framing:
Inheritance is about relationship and reuse.
Polymorphism is about interchangeable behavior behind the same method call.

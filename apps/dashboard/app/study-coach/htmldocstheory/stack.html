Technical Interview Study Page

Stack

A core data structure built around the LIFO principle: Last In, First Out. This page focuses on interview understanding, intuition, common traps, and how to explain the concept clearly.

Data Structures LIFO DFS Call Stack Interview Fundamentals

Definition

A stack is a data structure that follows the rule Last In, First Out. The last element you add is the first one you remove.

Simple version

Think of a stack like a pile of plates: you place plates on top, and you also take them from the top.

Intuition

A stack exists for situations where the most recent thing is the first thing you need to access. It is perfect for reversing order naturally.

What problem does it solve?

It helps manage operations that must be undone, returned from, or processed in reverse order.

Without a stack

Function calls, DFS traversal, undo systems, and parenthesis matching would be much harder to organize cleanly.

Mental Model

Last plate placed on the pile = first plate removed from the pile.
Top ↓ [ Plate 3 ] [ Plate 2 ] [ Plate 1 ]

You do not remove from the middle. You only interact with the top.

Core Operations

Operation Meaning Why it is fast
push(x) Adds an element on top of the stack You only touch the top
pop() Removes and returns the top element You only touch the top
peek() Returns the top element without removing it You only look at the top
Common interview correction

The correct term is peek, not peak. peek means “take a quick look.”

ASCII Visualization

After one pop

Step-by-Step Example

const stack = [];

stack.push(1);
stack.push(2);
stack.push(3);

console.log(stack.pop());  // 3
console.log(stack.peek?.()); // optional if custom stack exists
console.log(stack.pop());  // 2
Step 1
push(1)
Stack becomes: [1]
Step 2
push(2)
Stack becomes: [1, 2]
Step 3
push(3)
Stack becomes: [1, 2, 3]
Step 4
pop() returns 3
Because the last added comes out first
Key interview sentence

The reason pop() returns 3 is that a stack does not care about insertion order from the beginning; it only cares about the most recent item on top.

Implementation Example

class Stack {
  constructor() {
    this.items = [];
  }

  push(value) {
    this.items.push(value);
  }

  pop() {
    if (this.isEmpty()) return undefined;
    return this.items.pop();
  }

  peek() {
    if (this.isEmpty()) return undefined;
    return this.items[this.items.length - 1];
  }

  isEmpty() {
    return this.items.length === 0;
  }

  size() {
    return this.items.length;
  }
}

const stack = new Stack();
stack.push(10);
stack.push(20);
stack.push(30);

console.log(stack.peek()); // 30
console.log(stack.pop());  // 30
console.log(stack.pop());  // 20
console.log(stack.size()); // 1

Line-by-line explanation

  • this.items = [] stores the internal data.
  • push(value) adds to the top.
  • pop() removes from the top.
  • peek() reads the top without changing the stack.
  • isEmpty() helps avoid invalid removals.
  • size() tells you how many elements are currently stored.

Complexity

Operation Time Space Intuition
push O(1) O(n) total for storing n elements You add only at the top
pop O(1) You remove only from the top
peek O(1) You inspect only the top
Interview-friendly explanation

Time is O(1) because we never scan the structure. We only work with the top. Space is O(n) because storing more elements requires proportionally more memory.

Real-World Use Cases

1. Call Stack

Every function call is pushed onto the call stack. When the function finishes, it is popped.

2. DFS

Depth First Search can use an explicit stack to go deep before backtracking.

3. Undo / Redo

The latest action is stored on top, so it is the first thing that gets undone.

4. Expression Parsing

Matching parentheses and evaluating expressions often rely on stack behavior.

Call Stack Connection

function a() {
  b();
}

function b() {
  c();
}

function c() {
  console.log("hello");
}

a();
Call stack during execution: c() b() a() global()

When c() finishes, it leaves first. Then b(), then a(). That is stack behavior in real execution.

Stack in DFS

function dfs(graph, start) {
  const stack = [start];
  const visited = new Set();

  while (stack.length > 0) {
    const node = stack.pop();

    if (visited.has(node)) continue;
    visited.add(node);

    console.log(node);

    for (const neighbor of graph[node]) {
      if (!visited.has(neighbor)) {
        stack.push(neighbor);
      }
    }
  }
}
Why stack fits DFS

DFS wants to go deeper immediately. A stack naturally supports this because the most recently discovered node is processed next.

Classic Interview Problem: Valid Parentheses

function isValid(s) {
  const stack = [];
  const pairs = {
    ")": "(",
    "]": "[",
    "}": "{"
  };

  for (const ch of s) {
    if (ch === "(" || ch === "[" || ch === "{") {
      stack.push(ch);
    } else {
      const top = stack.pop();
      if (top !== pairs[ch]) return false;
    }
  }

  return stack.length === 0;
}

Main idea

  • Opening bracket → push it.
  • Closing bracket → pop the last opening bracket.
  • If they do not match, the string is invalid.
  • If the stack is not empty at the end, the string is invalid.

Common Mistakes / Confusions

Mistake 1

Confusing stack as a data structure with stack memory. They are related in idea, but they are not the same thing.

Mistake 2

Saying you can remove from the middle. You cannot. A true stack only allows access to the top.

Mistake 3

Forgetting that recursion uses the call stack internally. Deep recursion can fail with stack overflow.

Mistake 4

Saying peak instead of peek.

Bug Pattern: Stack Overflow

function f() {
  return f();
}

f();

Each function call adds a new frame to the call stack. Since this function never stops, the stack keeps growing until the runtime throws an error such as:

RangeError: Maximum call stack size exceeded
Why it happens

There is no base case, so the recursive calls never stop. More calls means more stack frames.

Comparison: Stack vs Queue

Structure Rule Useful for Mental picture
Stack LIFO DFS, undo, call stack Pile of plates
Queue FIFO BFS, scheduling, task processing People standing in line
Fast way to remember

Stack = newest first.
Queue = oldest first.

Interview Explanation Version

“A stack is a data structure that follows the Last In, First Out principle. The last item added is the first one removed. The main operations are push, pop, and peek, and they are typically O(1) because we only interact with the top element. Stacks are commonly used in call stacks, DFS, undo systems, and parenthesis matching problems.”

Pattern to Remember

If the problem says “go back,” “undo,” “most recent,” “nested,” or “match opening and closing symbols,” think stack.

Final Takeaway

Stack is one of the most important foundational structures in computer science because it appears both as an explicit data structure and as a hidden runtime mechanism through the call stack.

For interviews, the most important things to remember are:

  • LIFO behavior
  • push, pop, peek
  • O(1) time for top operations
  • Used in DFS, call stack, undo, parentheses
  • Deep recursion can cause stack overflow

Binary Tree

Structuri ierarhice, parcurgeri recursive și intuiția din spatele fiecărei operații.

Tree Recursion DFS / BFS Fundamental O(log n) BST O(n) traversal

📐 Definiția simplă

Un Binary Tree este o structură de date ierarhică în care fiecare nod are cel mult 2 copii — numiți copilul stâng și copilul drept.

Nodul de sus = root (rădăcina). Nodurile fără copii = frunze (leaves). Este baza pentru BST, Heap, Trie și mulți alți algoritmi fundamentali.

💡 Intuiția — De ce există?

Problema: Dacă stochezi date într-o listă, căutarea unui element durează O(n) — trebuie să parcurgi totul unul câte unul.
Binary Tree rezolvă: organizarea datelor ierarhic, astfel încât la fiecare pas poți elimina jumătate din spațiul de căutare → O(log n).
Fără arbori binari: sistemele de fișiere, bazele de date (indexuri SQL), compilatoarele (AST) și Git ar fi dramatic mai lente sau imposibil de implementat eficient.

🧠 Mental Model

Imaginează-ți un turneu de tenis cu eliminare directă. La fiecare meci (nod), există exact 2 jucători (copil stâng + copil drept). Câștigătorul avansează sus (spre rădăcină). Tragi o linie de sus în jos = parcurgi arborele.

Sau mai simplu: o familie la o reuniune. Bunicul stă în centru (root). El are 2 copii. Fiecare copil are maxim 2 copii. Când cauți pe cineva, la fiecare întrebare, jumătate din familie dispare din căutare.

class Node {
  constructor(value) {
    this.value = value;  // datele stocate
    this.left  = null;   // pointer copil stâng
    this.right = null;   // pointer copil drept
  }
}

// Construim manual un arbore
const root       = new Node(10);
root.left        = new Node(5);
root.right       = new Node(15);
root.left.left   = new Node(3);
root.left.right  = new Node(7);
root.right.right = new Node(20);

🔄 Cele 3 parcurgeri esențiale

In-Order
Stânga → Rădăcină → Dreapta
✅ Pe BST → valori sortate. Rezultat: 3, 5, 7, 10, 15, 20
Pre-Order
Rădăcină → Stânga → Dreapta
✅ Copiere arbore, serializare. Rezultat: 10, 5, 3, 7, 15, 20
Post-Order
Stânga → Dreapta → Rădăcină
✅ Ștergere arbore, calcul expresii. Rezultat: 3, 7, 5, 20, 15, 10
javascript — toate cele 3 parcurgeri
// IN-ORDER: stânga → rădăcină → dreapta
// De ce? — vizităm tot ce e mai mic, apoi nodul, apoi tot ce e mai mare
function inOrder(node) {
  if (node === null) return;  // ← CAZUL DE BAZĂ — esențial!
  inOrder(node.left);
  console.log(node.value);   // procesăm la mijloc
  inOrder(node.right);
}

// PRE-ORDER: rădăcină → stânga → dreapta
function preOrder(node) {
  if (node === null) return;
  console.log(node.value);   // procesăm PRIMUL
  preOrder(node.left);
  preOrder(node.right);
}

// POST-ORDER: stânga → dreapta → rădăcină
function postOrder(node) {
  if (node === null) return;
  postOrder(node.left);
  postOrder(node.right);
  console.log(node.value);   // procesăm ULTIMUL
}

🚶 Exemplu pas cu pas — Max Depth

Problemă: Găsește adâncimea maximă a unui Binary Tree (LeetCode #104). Arborele de mai sus are adâncimea 3.
  1. Identificăm cazul de bază: dacă nodul este null, adâncimea este 0.
    De ce? — Recursie fără caz de bază = Stack Overflow garantat.
  2. Apelăm recursiv pe copilul stâng și pe cel drept pentru a obține adâncimea lor.
    De ce? — Problema se descompune: adâncimea unui nod = 1 + max(adâncime stânga, adâncime dreapta).
  3. Returnăm 1 + Math.max(left, right) — cel mai lung drum spre o frunză.
    De ce max? — Vrem drumul cel mai LUNG, nu cel mai scurt.
javascript — maxDepth (soluție finală)
function maxDepth(root) {
  // Pasul 1: cazul de bază
  if (root === null) return 0;

  // Pasul 2: rezolvăm subproblemele (recursie)
  const leftDepth  = maxDepth(root.left);
  const rightDepth = maxDepth(root.right);

  // Pasul 3: combinăm rezultatele
  return 1 + Math.max(leftDepth, rightDepth);
}

// Execuție pe arborele nostru:
//
//   maxDepth(10)
//     maxDepth(5)
//       maxDepth(3) → 1 + max(0,0) = 1
//       maxDepth(7) → 1 + max(0,0) = 1
//     → 1 + max(1,1) = 2
//     maxDepth(15)
//       maxDepth(20) → 1 + max(0,0) = 1
//     → 1 + max(0,1) = 2
//   → 1 + max(2,2) = 3  ✅

console.log(maxDepth(root)); // → 3

⚠️ Greșeli comune & Bug-uri

❌ Bug #1 — Uiți cazul de bază în recursie

Fără if (node === null) return, recursia continuă la infinit → Stack Overflow.

javascript — buggy vs correct
// ❌ GREȘIT — lipsește cazul de bază
function height(node) {
  return 1 + Math.max(height(node.left), height(node.right));
  // → RangeError: Maximum call stack size exceeded!
}

// ✅ CORECT
function height(node) {
  if (node === null) return 0;  // ← OBLIGATORIU
  return 1 + Math.max(height(node.left), height(node.right));
}
❌ Bug #2 — Confuzi Binary Tree cu BST

Un Binary Tree simplu NU garantează că valorile sunt ordonate. Proprietatea de ordonare aparține BST-ului.

javascript — BT vs BST
// Binary Tree VALID (nu are reguli de ordine):
//       10
//      /  \
//     20    5    ← 20 pe stânga lui 10? OK în BT, INVALID în BST!

// BST VALID (stânga < rădăcină < dreapta):
//       10
//      /  \
//     5    20   ← corect: 5 < 10 < 20
❌ Bug #3 — In-Order pe BT simplu ≠ valori sortate

In-Order dă valori sortate NUMAI pe BST. Pe un Binary Tree fără proprietatea de ordonare, rezultatul e impredictibil.

🪤 Trick Questions — Capcane de interviu

Capcana #1: „Un arbore cu un singur nod — câte frunze are?"
→ Răspuns: 1. Rădăcina este și frunză când nu are copii. Mulți zic 0.
Capcana #2: „Poate un Binary Tree să aibă înălțimea O(n)?"
→ DA! Un arbore degenerat (fiecare nod un singur copil) e practic o listă înlănțuită. BST fără echilibrare poate degenera la O(n) dacă inserezi datele sortat.
Capcana #3: „In-Order traversal pe orice Binary Tree dă valori sortate?"
→ NU! Garantat sortate NUMAI dacă e BST.
Capcana #4: „Echilibrat = Perfect?"
→ NU! Echilibrat înseamnă că diferența de înălțime între subarbori e ≤ 1. Perfect înseamnă că toate nivelele sunt complet pline.

👶 Feynman Technique

Imaginează-ți că vrei să găsești un număr dintr-o carte de telefon cu un milion de numere. Dacă le citești unul câte unul, durează mult. Dar dacă deschizi cartea la mijloc și întrebi „e mai mare sau mai mic?", elimini jumătate. Faci asta din nou și din nou. Un Binary Tree funcționează exact așa — la fiecare nod, mergi ori la stânga (mai mic) ori la dreapta (mai mare). Cu 1.000.000 de numere, găsești pe oricine în doar ~20 de întrebări!

🎯 Răspuns de interviu (30 secunde)

Un Binary Tree este o structură de date ierarhică unde fiecare nod are cel mult doi copii — stâng și drept. Este util pentru că organizează datele recursiv, permițând operații eficiente: pe un BST echilibrat, căutarea, inserarea și ștergerea se fac în O(log n). Cele trei parcurgeri esențiale sunt in-order, pre-order și post-order — fiecare utilă în contexte diferite: in-order pe BST produce valori sortate, pre-order e util pentru serializare, iar post-order pentru ștergere. La interviu, gândirea recursivă este cheia: la fiecare nod te întrebi ce trebuie să știi despre subarbori pentru a rezolva problema.

🔑 Pattern de reținut

✦ regula de aur pentru arbori

Când primești o problemă cu arbori binari, primul instinct = gândește recursiv. Întreabă-te: „Ce trebuie să știe nodul curent despre subarborii săi pentru a rezolva problema?" Dacă poți răspunde la asta, soluția recursivă apare natural.

Structura universală: if (!node) return valoare_implicita; → rezolvă stânga → rezolvă dreapta → combină rezultatele.

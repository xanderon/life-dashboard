Detect Cycle in Linked List
Easy Two Pointers Linked List Floyd's Algorithm Fast & Slow Pointers
Problem Statement

Given the head of a linked list, determine if the list has a cycle in it.

A cycle exists if some node can be reached again by continuously following the next pointer. Return true if there is a cycle, false otherwise.

Constraint to keep in mind: The problem asks for O(1) space in the follow-up, which immediately rules out the HashSet approach and points toward Floyd's algorithm.

Example 1 — Has cycle
Input: head = [3, 2, 0, -4] (tail connects to node at index 1)
Output: true
[3] → [2] → [0] → [-4]
       ↑__________________|
tail (-4) points back to node 2 → infinite loop
Example 2 — No cycle
Input: head = [1, 2] (tail connects to no node)
Output: false
[1] → [2] → null
Example 3 — Edge case
Input: head = [1]
Output: false
Single node, next = null → return false immediately
Main Idea — Intuition

The Tortoise & Hare

Imagine two runners on a track. One runs at 1× speed (slow), the other at 2× speed (fast).

  • If the track is straight → fast reaches the end (null) first. No cycle.
  • If the track is circular → fast will eventually lap slow and they meet. Cycle exists.

Why do they always meet? Think in relative terms: fast gains exactly 1 step on slow per iteration. Inside a cycle, the gap between them shrinks by 1 each round. Eventually the gap becomes 0 — they're on the same node.

Key insight: we only need two pointers and no extra memory. This is the O(1) space requirement the interviewer is looking for.

Both slow and fast start at head. Edge case check: if head or head.next is null, return false immediately — no cycle possible.

Final Solution
hasCycle.js · Floyd's Algorithm · O(n) time · O(1) space 
/**
 * Definition for singly-linked list node.
 * function ListNode(val) {
 *   this.val = val;
 *   this.next = null;
 * }
 */

/**
 * Floyd's Cycle Detection — Tortoise & Hare
 * @param {ListNode} head
 * @return {boolean}
 */
function hasCycle(head) {

  // ── EDGE CASE ─────────────────────────────────────────────────────
  // Empty list or single node → can't have a cycle.
  // Also prevents null-dereference errors below.
  if (!head || !head.next) return false;

  // ── INITIALIZE POINTERS ───────────────────────────────────────────
  // Both start at head. slow moves 1 step; fast moves 2 steps.
  // Starting at the same place is intentional — first advance happens
  // inside the loop before the equality check.
  let slow = head;
  let fast = head;

  // ── MAIN LOOP ─────────────────────────────────────────────────────
  // We need BOTH guards:
  //   fast !== null         → fast hasn't walked off the end yet
  //   fast.next !== null    → calling fast.next.next won't throw
  while (fast !== null && fast.next !== null) {

    // Advance slow by 1 step
    slow = slow.next;

    // Advance fast by 2 steps (gains 1 step on slow per iteration)
    fast = fast.next.next;

    // ── MEETING CHECK ──────────────────────────────────────────────
    // Compare REFERENCES (object identity), not .val!
    // Two different nodes can hold the same value — that's not a cycle.
    if (slow === fast) return true;  // They're on the same node → cycle!
  }

  // ── NO CYCLE ──────────────────────────────────────────────────────
  // fast reached null → the list has a definite end.
  return false;
}
▸ Show naive HashSet solution (O(n) space)
hasCycle-hashset.js · O(n) time · O(n) space 
function hasCycle(head) {
  // Store every visited node reference in a Set.
  // If we encounter a node we've seen before → cycle.
  const seen = new Set();

  let current = head;
  while (current !== null) {
    if (seen.has(current)) return true;  // Already visited → cycle!
    seen.add(current);                   // Mark as visited
    current = current.next;
  }

  return false;  // Reached null → no cycle
}
Line-by-Line Explanation
if (!head || !head.next) return false;
Edge case guard. Handles empty list and single-node list. A cycle requires at least 2 nodes with one pointing back.
→ Without this, head.next.next would throw a TypeError.
let slow = head; let fast = head;
Both start at head. The first real move happens inside the loop, so starting at the same position is safe — they won't trigger a false-positive meet on init.
while (fast !== null && fast.next !== null)
Two guards, both required. fast !== null prevents calling .next on null. fast.next !== null prevents calling .next.next when fast is the last node.
slow = slow.next; fast = fast.next.next;
Speed differential = 1 per step. This relative gain is what guarantees fast catches slow inside any cycle in at most cycle_length iterations.
if (slow === fast) return true;
Reference equality, not value! === on objects checks if they are the exact same object in memory. Two nodes with value 2 are not a cycle unless they are literally the same node.
return false;
Fast exited naturally. The only way to exit the while loop without returning true is if fast or fast.next became null → the list has an endpoint → no cycle.
Common Mistakes
⚠️
Comparing .val instead of references

if (slow.val === fast.val) is wrong. Two different nodes can have the same value. You need slow === fast to compare object identity (memory address).

⚠️
Missing the fast.next guard

Writing while (fast !== null) without checking fast.next !== null. If fast is the last node, fast.next.next throws a TypeError at runtime.

⚠️
Forgetting the edge case check

Jumping straight into the loop with an empty list or single-node list causes immediate crashes. Always guard with if (!head || !head.next) return false first.

⚠️
Using HashSet when O(1) space is required

HashSet is valid for LeetCode 141 but interviewers often follow up with "can you do it with constant space?" — always lead with Floyd's and mention HashSet as the naive alternative.

Complexity Analysis
Time Complexity
O(n)
slow visits at most n nodes before they meet or fast exits. Even inside a cycle, fast gains 1 step per iteration → meets slow in at most cycle_length steps.
Space Complexity
O(1)
Only two pointer variables, regardless of list length. No auxiliary data structure. This is the key advantage over the HashSet approach.

30-Second Interview Answer
"I'll use Floyd's cycle detection — two pointers, slow and fast. Slow advances one step per iteration, fast advances two steps. If there's no cycle, fast reaches null and we return false. If there's a cycle, fast will eventually lap slow inside the loop and they'll land on the same node, so we return true. Time complexity is O(n) and space is O(1) — just two pointer variables."
Pattern to Remember

Fast & Slow Pointers (Tortoise & Hare) is the pattern. Whenever you see:

  • Detect a cycle in any sequence / linked list
  • Find the entry point of a cycle (LeetCode 142)
  • Find the middle node of a linked list (when fast reaches end, slow is at mid)
  • Find a duplicate number in an array (LeetCode 287 — same algorithm!)
🐢 slow = head → +1 step 🐇 fast = head → +2 steps meet → cycle or midpoint

Bonus — find cycle entry point (LC 142): After slow and fast meet, reset slow to head. Advance both by 1 step at a time. Where they meet again is the entry node of the cycle. This works due to a beautiful mathematical property: the distance from head to entry equals the distance from the meeting point to entry (going forward inside the cycle).

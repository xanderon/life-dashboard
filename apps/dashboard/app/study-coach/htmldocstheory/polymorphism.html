Polymorphism in OOP

A clean interview-focused guide to what polymorphism really means, how it relates to inheritance, interfaces, abstract classes, duck typing, overriding, and runtime dispatch.

OOP Theory Interview Prep JavaScript TypeScript Design Fundamentals

Definition

Polymorphism means that the same method call can lead to different behavior depending on the actual object.

In practice: code works with a common contract such as a parent class or interface, while the concrete implementation is chosen at runtime.

same interface / same call → different behavior

Intuition

  • Lets you write generic code once and reuse it for many object types.
  • Removes big chains of if / switch based on type.
  • Makes systems easier to extend without changing existing calling code.
  • Supports cleaner design and the Open/Closed Principle.
Without polymorphism
  • Code becomes rigid and repetitive.
  • You often check types manually.
  • Adding a new behavior usually means modifying central logic.
  • That creates tighter coupling and more maintenance risk.

Mental Model

1

Define a common contract

A base class, abstract class, or interface defines a method like makeSound() or pay().

2

Create multiple implementations

Dog, Cat, ApplePay, RevolutPay each implement the same method differently.

3

Call through the generic type

The caller uses animal.makeSound() or payment.pay(100) without caring about the exact class.

4

Runtime chooses the real implementation

This is the key idea: the actual method is selected when the program runs, based on the concrete object.

Example — JavaScript Class Version

Classic subtype polymorphism using inheritance and method overriding.

class Animal {
  makeSound() {
    console.log("Some sound");
  }
}

class Dog extends Animal {
  makeSound() {
    console.log("Woof");
  }
}

class Cat extends Animal {
  makeSound() {
    console.log("Meow");
  }
}

const animals = [new Dog(), new Cat(), new Dog()];

animals.forEach(animal => animal.makeSound());

// Output:
// Woof
// Meow
// Woof

Example — Real-World Payment Version

Very good interview example because it shows one contract and multiple implementations.

class Payment {
  pay(amount) {
    throw new Error("Must implement pay()");
  }
}

class ApplePay extends Payment {
  pay(amount) {
    console.log("Apple Pay:", amount);
  }
}

class RevolutPay extends Payment {
  pay(amount) {
    console.log("Revolut Pay:", amount);
  }
}

function processPayment(payment) {
  payment.pay(100);
}

processPayment(new ApplePay());
processPayment(new RevolutPay());

Step-by-Step Explanation

  • A parent type defines a shared method such as makeSound() or pay().
  • Child classes keep the same method name and contract.
  • Each child provides its own internal implementation.
  • The caller uses the general type, not the specific implementation.
  • At runtime, the engine dispatches the call to the correct method.
  • That is why the same call produces different results.

How It Appears in JavaScript

Method overriding

A subclass defines a method with the same name as the parent method, replacing the inherited behavior.

class Animal {
  speak() {
    console.log("sound");
  }
}

class Dog extends Animal {
  speak() {
    console.log("woof");
  }
}

Line-by-Line Insight

  • class Animal defines the common API.
  • class Dog extends Animal means Dog inherits from Animal.
  • makeSound() in Dog overrides the parent version.
  • animals.forEach(...) treats all objects uniformly.
  • animal.makeSound() is the same call every time.
  • The output changes because the concrete object changes.

Comparison

Inheritance
  • Defines an is-a relationship.
  • Lets a child class inherit fields and methods.
  • Can help reuse structure or default behavior.
  • Does not automatically mean polymorphism.
Polymorphism
  • Focuses on a shared contract.
  • Same call, different concrete behavior.
  • Usually appears through overriding.
  • Its key mechanism is runtime dispatch.

Related Concepts That Commonly Get Confused

Encapsulation

Hides internal state and controls access to data.

private, protected, getters, setters.

Abstraction

Hides complexity and exposes only the essential interface.

You use something without needing to know all the internal details.

Interface / abstract class

These often define the contract used for polymorphism.

They help standardize method names and expected behavior.

Duck typing

Common in JavaScript: if an object has the required method, it can be used.

function makeSound(animal) {
  animal.speak();
}

Common Mistakes / Confusions

  • “Polymorphism = inheritance” → not exactly. Inheritance often enables it, but the core idea is shared contract + different behavior.
  • “Same behavior” → wrong. It is the same call, not the same result.
  • “Same class name” → wrong. The important part is the same method name / contract.
  • Forgetting runtime dispatch → this is the main mechanism interviewers want to hear.
  • Mixing overriding with overloading → overriding changes behavior in child classes; overloading is compile-time and not truly native in JavaScript.
  • Manual type checking everywhere → often a sign you are not using polymorphism well.

Interview Insights

What interviewers commonly test

  • Definition of polymorphism in simple words.
  • Difference between inheritance and polymorphism.
  • Overriding vs overloading.
  • Why runtime dispatch matters.
  • Can polymorphism exist through interfaces or duck typing?
  • Why it helps with extensibility and clean design.

Good phrases to say

  • “The code works with a generic type.”
  • “The actual implementation is chosen at runtime.”
  • “Same interface, different behavior.”
  • “It reduces type-based branching in the caller.”
  • “It helps write extensible code.”

Interview Explanation Version

30-second answer:
Polymorphism is the ability for different objects to respond differently to the same method call. Usually a base class, abstract class, or interface defines a common contract, and each concrete type provides its own implementation. The caller works with the generic type, while the actual method that runs is selected at runtime based on the real object.

Pattern to Remember

Inheritance gives you the relationship.
Polymorphism gives you the flexible behavior.
Runtime dispatch is what makes that flexibility happen.

Final Summary

  • Polymorphism means same call, different behavior.
  • It usually appears through overriding in child classes.
  • The caller works with a common contract.
  • The concrete method is chosen by runtime dispatch.
  • It is related to inheritance, interfaces, and abstract classes, but it is not identical to them.
  • In JavaScript, it also appears through prototype-based behavior and duck typing.

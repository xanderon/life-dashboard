Definition

Simple definition

Breadth-First Search (BFS) is a graph traversal algorithm that explores nodes level by level, starting from a source node.

It is especially useful for finding the shortest path in an unweighted graph, because the first time you reach a node, you reached it using the minimum number of edges.

Problem statement / what BFS solves

Why does BFS exist?

Suppose you have a graph and you want to know:

  • which nodes are reachable from a start node,
  • the minimum number of steps to reach a target,
  • or how to explore everything in increasing distance order.

BFS solves this by processing nodes in the exact order of their distance from the start.

Intuition

The key to BFS is not just “visit neighbors.” The real idea is: finish the current distance level before moving to the next one.

If a node is 1 edge away from the start, BFS will process it before any node that is 2 edges away. That is why BFS gives shortest path in unweighted graphs.

Mental model

Wave analogy

Imagine throwing a stone into water. The ripples spread outward in layers. BFS behaves the same way: it expands from the start node one “ring” at a time.

Social network analogy

First you visit your direct friends, then friends of friends, then the next circle after that. That is BFS: nearest first, farther later.

Visualization / ASCII diagram

Queue evolution:

Start: Queue = [A] Visited = {A} Pop A Add B, C Queue = [B, C] Pop B Add D, E Queue = [C, D, E] Pop C Add F Queue = [D, E, F] Pop D Queue = [E, F] Pop E Queue = [F] Pop F Queue = []

How BFS works conceptually

Step 1: Put the start node into the queue.
Step 2: Mark the start node as visited.
Step 3: While the queue is not empty, dequeue the front node.
Step 4: Check whether it is the target (if the problem asks for one).
Step 5: Iterate through its neighbors.
Step 6: For each unvisited neighbor, mark it visited and enqueue it.
Important implementation detail

In BFS, you usually mark a node as visited when you enqueue it, not when you dequeue it. That prevents duplicates from entering the queue multiple times.

Example graph + code

Adjacency list representation:

const graph = {
  A: ["B", "C"],
  B: ["D", "E"],
  C: ["F"],
  D: [],
  E: [],
  F: []
};

Basic BFS that searches for a target:

function bfs(graph, start, target) {
  const queue = [start];
  const visited = new Set([start]);

  while (queue.length > 0) {
    const node = queue.shift();

    if (node === target) {
      return true;
    }

    for (const neighbor of graph[node]) {
      if (!visited.has(neighbor)) {
        visited.add(neighbor);
        queue.push(neighbor);
      }
    }
  }

  return false;
}

Why this matters

Because BFS processed all nodes by distance, the first time it found E, it found it using the minimum number of edges from A.

Line-by-line explanation of the BFS code

Code Meaning
const queue = [start]; The queue stores nodes that still need to be processed.
const visited = new Set([start]); The visited set prevents cycles and duplicate work.
while (queue.length > 0) Keep exploring until there are no more reachable nodes left.
const node = queue.shift(); Take the oldest inserted node first. This FIFO behavior is what preserves level order.
if (node === target) If we only need existence or shortest path discovery, we can stop early here.
for (const neighbor of graph[node]) Explore all adjacent nodes.
if (!visited.has(neighbor)) Only process neighbors we have not already discovered.
visited.add(neighbor); Mark immediately when enqueuing to avoid adding the same node many times.
queue.push(neighbor); Schedule the neighbor to be processed later, after earlier nodes in the same wave.

Complexity

Time complexity

O(V + E)

Each vertex is processed at most once, and each edge is examined at most once.

Space complexity

O(V)

The queue and the visited set can both grow up to the number of vertices.

BFS vs DFS

BFS

  • Uses a queue
  • Explores level by level
  • Best for shortest path in unweighted graphs
  • Usually uses more memory on wide graphs

DFS

  • Uses a stack or recursion
  • Explores deep first
  • Good for backtracking, cycle detection, topological ideas
  • Does not guarantee shortest path in unweighted graphs
Important nuance

Saying “DFS is the same algorithm but with a stack” is close, but not fully precise. They are related traversal patterns, but the traversal order and what they are best at are different in a meaningful way.

Common mistakes / confusions

Mistake 1 — forgetting the main point

Many candidates describe the mechanics but forget the key value: BFS processes nodes by distance / by level.

Mistake 2 — forgetting shortest path

The most interview-important thing to say is: BFS finds the shortest path in an unweighted graph.

Mistake 3 — not using a visited set

Without a visited structure, cyclic graphs can cause infinite processing.

Mistake 4 — marking visited too late

If you wait until dequeue time, the same node may enter the queue multiple times.

Mistake 5 — saying BFS is only “for unweighted graphs”

More precise phrasing: BFS is a general traversal algorithm, and it is used for shortest path specifically when the graph is unweighted.

Bug example: missing visited set

function brokenBfs(graph, start) {
  const queue = [start];

  while (queue.length > 0) {
    const node = queue.shift();

    for (const neighbor of graph[node]) {
      queue.push(neighbor);
    }
  }
}
Why this is broken

In a cyclic graph, the same nodes keep getting re-added forever.

Real-world use cases

Shortest path on unweighted graphs

Examples: minimum number of transformations, minimum number of moves, fewest jumps, shortest route in a grid without weights.

Social network layers

Friends, friends of friends, then the next circle. This is classic BFS thinking.

Grid problems

Many interview BFS problems are really matrix/grid problems where each cell acts like a node.

Network / dependency exploration

Reachability checks, spreading processes, level discovery, distance-from-source logic.

Brute force comparison

Without BFS

You might explore paths in a messy order, repeat work, or fail to preserve distance order. That makes shortest-path reasoning much harder.

With BFS

The algorithm is structured around a queue, which naturally enforces the correct level order. That is the reason the traversal is both clean and optimal for unweighted shortest-path questions.

Interview explanation version

Good 30-second answer:

Breadth-First Search is a graph traversal algorithm that explores nodes level by level, starting from a source node. It uses a queue to process nodes in FIFO order and a visited set to avoid revisiting nodes, especially in graphs with cycles. BFS is particularly important because it finds the shortest path in an unweighted graph: the first time we reach a node, we reached it using the minimum number of edges. Its time complexity is O(V + E) and its space complexity is O(V).

Pattern to remember

If the problem says:

  • minimum number of steps,
  • shortest path in an unweighted graph,
  • level-by-level exploration,
  • nearest first,
  • friends-of-friends,
  • grid + minimum moves,

then BFS should be one of your first thoughts.

Final takeaway

What matters most

The mechanical part of BFS is easy to memorize: queue + visited + loop. The deeper understanding is this: the queue is what guarantees level order, and level order is why BFS gives shortest path in unweighted graphs.

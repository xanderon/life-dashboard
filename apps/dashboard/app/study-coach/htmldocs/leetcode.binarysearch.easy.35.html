LeetCode 35 — Search Insert Position

Problem

Given a sorted array of distinct integers and a target value, return the index if the target is found. If not, return the index where it would be if it were inserted in order.

You must write an algorithm with O(log n) runtime complexity.

Examples

  • Input: nums = [1,3,5,6], target = 5 → Output: 2
  • Input: nums = [1,3,5,6], target = 2 → Output: 1
  • Input: nums = [1,3,5,6], target = 7 → Output: 4

Intuition

Because the array is sorted and the problem requires O(log n), the correct pattern is binary search.

At each step:

  • Look at the middle element.
  • If it matches the target, return its index.
  • If it is smaller than the target, search the right half.
  • If it is larger than the target, search the left half.

If the target is not found, the correct insert position is exactly where left ends up.

JavaScript Solution

/**
 * @param {number[]} nums
 * @param {number} target
 * @return {number}
 */
var searchInsert = function(nums, target) {
    // Start of the search range
    let left = 0;
    let right = nums.length - 1;

    // Keep searching while the range is valid
    while (left <= right) {
        // Find the middle index of the current search range
        let mid = Math.floor((left + right) / 2);

        // If the middle value is exactly the target, return its index
        if (nums[mid] === target) {
            return mid;
        }

        // If the middle value is smaller than target,
        // the target must be on the right side
        if (nums[mid] < target) {
            left = mid + 1;
        } 
        // Otherwise, the middle value is greater than target,
        // so the target must be on the left side
        else {
            right = mid - 1;
        }
    }

    // If the target was not found,
    // left is the correct insert position
    return left;
};

Step-by-Step Explanation

  • left starts at index 0.
  • right starts at the last index.
  • We repeatedly calculate mid as the middle of the current range.
  • If nums[mid] === target, we found the answer.
  • If nums[mid] < target, the target must be to the right, so move left.
  • If nums[mid] > target, the target must be to the left, so move right.
  • If the loop ends, the target does not exist in the array.
  • At that point, left is the exact place where the target should be inserted.

Why Return left?

When the loop finishes, it means the target was not found.

At that moment:

  • All indices before left contain values smaller than the target.
  • All indices after right contain values greater than the target.
  • So left is exactly the position where the target belongs.

Complexity

  • Time Complexity: O(log n)
    We cut the search space in half on every iteration.
  • Space Complexity: O(1)
    We only use a few variables and no extra data structures.

Pattern

Binary Search

This problem is a classic binary search problem where we either:

  • find the target, or
  • find the position where it should be inserted

Common Mistakes

  • Comparing mid with target instead of nums[mid] with target.
  • Forgetting to return left after the loop ends.
  • Using linear search, which would be O(n) instead of O(log n).
  • Updating the pointers incorrectly, for example using left = mid or right = mid and causing an infinite loop.

Mental Model

Think of this problem as:

"Find the first position where the target could stand in sorted order."

If the number exists, return its index. If it does not exist, return the position where it should be inserted.

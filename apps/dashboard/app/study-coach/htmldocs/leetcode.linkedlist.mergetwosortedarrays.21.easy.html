21. Merge Two Sorted Lists

Technical interview study page — linked list fundamentals, intuition, walkthrough, final JavaScript solution, and common interview mistakes.

Easy Linked List Two Pointers Pointer Manipulation Merge Pattern

1. Problem Statement

Problem

You are given the heads of two sorted linked lists list1 and list2.

Merge the two lists into one sorted list. The list should be made by splicing together the nodes of the first two lists.

Return the head of the merged linked list.

2. Examples

Example 1

Input: list1 = [1,2,4], list2 = [1,3,4]

Output: [1,1,2,3,4,4]

Example 2

Input: list1 = [], list2 = []

Output: []

Example 3

Input: list1 = [], list2 = [0]

Output: [0]

3. Main Idea / Intuition

Core Idea

We keep one pointer on the current node of list1 and one pointer on the current node of list2. At each step, we take the smaller current node and attach it to the result.

Because both input lists are already sorted, choosing the smaller front node each time guarantees that the final result stays sorted.

Important Concept

The input shown as [1,2,4] is only a friendly display format. In the actual function, list1 and list2 are not arrays. They are linked lists, which means chains of nodes.

Each node looks like this:

{
  val: 1,
  next: {
    val: 2,
    next: {
      val: 4,
      next: null
    }
  }
}

4. Step-by-step Walkthrough

Setup

We use a dummy node so we can build the result list easily without special handling for the first real node.

dummy(0) -> null tail points to dummy list1: 1 -> 2 -> 4 -> null list2: 1 -> 3 -> 4 -> null

Step 1 — Compare 1 and 1

list1.val <= list2.val is true, so attach the node from list1.

Result: dummy -> 1 tail moves to that 1 list1: 2 -> 4 list2: 1 -> 3 -> 4

Step 2 — Compare 2 and 1

This time list2 is smaller, so attach the node from list2.

Result: dummy -> 1 -> 1 tail moves to the second 1 list1: 2 -> 4 list2: 3 -> 4

Step 3 — Compare 2 and 3

Take the node from list1.

Result: dummy -> 1 -> 1 -> 2 list1: 4 list2: 3 -> 4

Step 4 — Compare 4 and 3

Take the node from list2.

Result: dummy -> 1 -> 1 -> 2 -> 3 list1: 4 list2: 4

Step 5 — Compare 4 and 4

Take the node from list1 because we used <=.

Result: dummy -> 1 -> 1 -> 2 -> 3 -> 4 list1: null list2: 4

Step 6 — One list is finished

The loop stops because list1 === null. The remaining nodes in list2 are already sorted, so we attach them directly.

Final: dummy -> 1 -> 1 -> 2 -> 3 -> 4 -> 4

Why return dummy.next?

dummy is only a fake helper node. The real merged list starts at the first node after it, which is dummy.next.

5. Final JavaScript Solution

/**
 * Definition for singly-linked list.
 * function ListNode(val, next) {
 *     this.val = (val === undefined ? 0 : val);
 *     this.next = (next === undefined ? null : next);
 * }
 */

/**
 * @param {ListNode} list1
 * @param {ListNode} list2
 * @return {ListNode}
 */
var mergeTwoLists = function(list1, list2) {
    // Create a fake starting node to simplify result building
    let dummy = new ListNode(0);

    // tail always points to the last node in the merged list
    let tail = dummy;

    // Compare current nodes while both lists still have nodes
    while (list1 !== null && list2 !== null) {
        if (list1.val <= list2.val) {
            // Attach the current node from list1
            tail.next = list1;

            // Move forward in list1
            list1 = list1.next;
        } else {
            // Attach the current node from list2
            tail.next = list2;

            // Move forward in list2
            list2 = list2.next;
        }

        // Move tail to the node we just attached
        tail = tail.next;
    }

    // Attach the remaining nodes from whichever list is not empty
    tail.next = list1 || list2;

    // Skip the fake node and return the real head
    return dummy.next;
};

6. Line-by-line Explanation

Code Explanation
let dummy = new ListNode(0); Create a helper node so we can attach nodes easily without worrying about how to initialize the head of the result.
let tail = dummy; tail tracks the last node in the merged list.
while (list1 !== null && list2 !== null) Keep merging while both lists still have a current node available.
if (list1.val <= list2.val) Compare the values of the two current nodes and choose the smaller one.
tail.next = list1; Attach the current list1 node to the merged list.
list1 = list1.next; Move the list1 pointer to its next node.
tail.next = list2; Attach the current list2 node when it is smaller.
list2 = list2.next; Move the list2 pointer forward.
tail = tail.next; Advance tail because the merged list has grown by one node.
tail.next = list1 || list2; Once one list ends, attach the remaining nodes from the other list directly.
return dummy.next; Return the first real node, not the fake helper node.

7. Common Mistakes

Mistakes to Watch For
  • Treating the input like arrays. These are linked lists, not arrays. You move with .next, not with indexes.
  • Using a for loop. A linked list does not give you direct indexed access like arr[i].
  • Forgetting to move tail. If you skip tail = tail.next, you keep writing in the same place.
  • Moving the wrong pointer. If you attach a node from list1, you must move list1, not list2.
  • Returning dummy instead of dummy.next. That would include the fake starting node.
  • Forgetting the leftover nodes. After the loop, one list may still contain nodes that must be attached.

8. Complexity

Time Complexity

O(n + m)

Each node from both lists is visited once. If n is the size of list1 and m is the size of list2, total work is proportional to n + m.

Space Complexity

O(1)

We only use a few pointers like dummy and tail. We are reusing the existing nodes instead of building a large extra structure.

9. Interview Explanation Version

How to say it out loud

“I use two pointers, one for each sorted linked list, and a dummy node to simplify building the merged result. While both lists still have nodes, I compare their current values, attach the smaller node to the result, move the pointer of the list I took from, and then move the tail of the merged list. When one list ends, I attach the rest of the other list directly because it is already sorted. Finally, I return dummy.next because dummy is only a helper node.”

10. Pattern to Remember

Mental Model

Think of three pointers:

  • list1 points to the current node in the first list
  • list2 points to the current node in the second list
  • tail points to the last node in the merged result

At each step:

  • compare list1.val and list2.val
  • attach the smaller node to tail.next
  • move that list’s pointer forward
  • move tail forward

11. Optional Brute Force Comparison

Less Interview-Friendly Approach

A brute-force style approach would be:

  • read all node values into an array
  • sort the array
  • build a new linked list from the sorted values

This works, but it is weaker for interviews because:

  • it ignores the linked list structure
  • it uses extra space
  • it misses the intended pointer manipulation pattern
// Brute force idea only - not the preferred interview solution
var mergeTwoLists = function(list1, list2) {
    let values = [];

    while (list1 !== null) {
        values.push(list1.val);
        list1 = list1.next;
    }

    while (list2 !== null) {
        values.push(list2.val);
        list2 = list2.next;
    }

    values.sort((a, b) => a - b);

    let dummy = new ListNode(0);
    let current = dummy;

    for (const value of values) {
        current.next = new ListNode(value);
        current = current.next;
    }

    return dummy.next;
};

12. Final Takeaway

What to Remember

This problem is not really about sorting from scratch. It is about understanding how linked lists work: each variable like list1 or list2 points to the current node, not to an array.

Once that clicks, the rest becomes a clean merge process with a dummy node and a tail pointer.

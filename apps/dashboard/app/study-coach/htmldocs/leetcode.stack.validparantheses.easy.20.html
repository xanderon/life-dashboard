20. Valid Parentheses

A classic Stack interview problem. The key idea is to track the most recent opening bracket that still needs to be closed, and verify that each closing bracket matches it in the correct order.

Easy Stack String Hash Map / Object Interview Pattern

Problem Statement

Given a string s containing just the characters ( ) { } [ ], determine if the input string is valid.

An input string is valid if:

  • Open brackets are closed by the same type of brackets.
  • Open brackets are closed in the correct order.
  • Every closing bracket has a corresponding opening bracket.

Constraint: 1 <= s.length <= 10^4

Examples

Example 1

Input: "()"

Output: true

Example 2

Input: "()[]{}"

Output: true

Example 3

Input: "(]"

Output: false

Example 4

Input: "([])"

Output: true

Example 5

Input: "([)]"

Output: false

Main Idea / Intuition

Mental model

A stack stores opening brackets that are still waiting to be closed.

  • When we see an opening bracket, we push it onto the stack.
  • When we see a closing bracket, it must match the most recent opening bracket.
  • If it does not match, the string is invalid.

This is why a stack is the right data structure: the last opening bracket must be the first one to close.

We also use a small pairs object to quickly check what opening bracket should match a given closing bracket.

Step-by-step Walkthrough

Walkthrough for "([])"

1. Read (
Opening bracket → push it
Stack: [ "(" ]
2. Read [
Opening bracket → push it
Stack: [ "(", "[" ]
3. Read ]
Closing bracket → pop stack
Popped: "["
Match? Yes
4. Read )
Closing bracket → pop stack
Popped: "("
Match? Yes

End of string. Stack is empty → valid.

Why "([)]" fails

  • Push (
  • Push [
  • Read )
  • The top of the stack is [, but ) needs (
  • Wrong order → invalid

Final JavaScript Solution

/**
 * @param {string} s
 * @return {boolean}
 */
var isValid = function(s) {
  const stack = [];

  const pairs = {
    ')': '(',
    ']': '[',
    '}': '{'
  };

  for (const char of s) {
    // If it is an opening bracket, push it to the stack
    if (char === '(' || char === '[' || char === '{') {
      stack.push(char);
    } else {
      // If stack is empty, there is nothing to match
      if (stack.length === 0) {
        return false;
      }

      // Take the most recent opening bracket
      const last = stack.pop();

      // Check if current closing bracket matches it
      if (pairs[char] !== last) {
        return false;
      }
    }
  }

  // Valid only if no unmatched opening brackets remain
  return stack.length === 0;
};

Line-by-line Explanation

Code What it does
const stack = []; Creates the stack used to store opening brackets.
const pairs = { ')': '(', ']': '[', '}': '{' }; Maps each closing bracket to the opening bracket it expects.
for (const char of s) Loops through each character in the string.
if (char === '(' || char === '[' || char === '{') Checks whether the current character is an opening bracket.
stack.push(char) Saves the opening bracket for later matching.
if (stack.length === 0) If a closing bracket appears and the stack is empty, the string is invalid.
const last = stack.pop(); Removes the most recent opening bracket.
if (pairs[char] !== last) If the popped opening bracket does not match the current closing bracket, return false.
return stack.length === 0; After processing all characters, the string is valid only if all opening brackets were matched.

Common Mistakes

1. Forgetting to check empty stack

If the string starts with ), ], or }, there is nothing to match. That must return false immediately.

2. Comparing only adjacent characters

This fails for nested cases like "([])". Matching is about the most recent unclosed opener, not the previous character.

3. Forgetting the final stack check

A string like "(((" never mismatches during the loop, but it is still invalid because open brackets remain.

4. Mixing map directions

Be consistent. In this solution, the object is closing -> opening, because the stack stores opening brackets.

Complexity

Time Complexity: O(n)

We scan the string once, and each bracket is pushed or popped at most one time.

Space Complexity: O(n)

In the worst case, the stack may store all opening brackets, such as "((([{{".

Interview Explanation Version

“I would solve this using a stack. As I iterate through the string, I push every opening bracket onto the stack. When I see a closing bracket, I check whether the stack is empty; if it is, the string is invalid. Otherwise, I pop the most recent opening bracket and verify that it matches the current closing bracket using a small lookup object. At the end, the string is valid only if the stack is empty.”

Pattern to Remember

Use a stack when you need to validate nested structure
  • Parentheses
  • Brackets
  • HTML/XML-like tag matching
  • Nested expressions

Short memory hook: “Last opener must be closed first.”

Optional Brute Force Comparison

A less structured idea would be to repeatedly remove valid pairs like (), [], and {} until nothing changes.

That can work, but it is less elegant and usually less efficient than a stack solution. The stack approach is the standard interview answer because it is direct, clean, and scales well.
